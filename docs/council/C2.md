# Council C2: the optimizer

Question: is the formulation correct, the risk bound honest, and the economics realistic?
Members: council-quant, council-controller, council-ramp-engineer.
Files: `tempo/optimize/` (milp.py, options.py, cash.py, certify.py, engine.py, baselines.py, evaluate.py, cash_value.py, explain.py, stats.py, run.py), `tempo/forecast/`, `tempo/assumptions.py`, `docs/RESULTS.md`, `data/demo/calibration.json`, `tests/unit/test_milp.py`, `tests/unit/test_planning.py`, `docs/DECISIONS.md`.

## Chair's position (written before reading any verdict)
The reduced formulation is exact and the tests (brute force, reduced = full, recount <= K) back it. The bound is honest in the narrow sense: seed B decides with a Bonferroni-corrected Wilson bound and seed C reports, and a true-model column shows 3.3% vs 2.4% under the fitted model. My concerns: (1) certification passes at the first ladder step with a large margin (B bound 2.3% vs 5%), so the ladder starting at K = 4 leaves value on the table; that is the directive's choice but worth naming. (2) The tension thresholds were missed and a fallback rule was pre-registered and used; the README must say so. (3) FINANCE_EARLY carries a made-up 1%/30-day fee and is chosen 16 times; it inflates value if the fee is unrealistic, so the README must label it an assumption. (4) Statement-date card float and the horizon-end clamp deserve a second look for end effects.
